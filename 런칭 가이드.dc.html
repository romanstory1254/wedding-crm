프로토타입을
실제 서비스로 만드는 순서

지금 만든 화면은 브라우저 안에서만 도는 프로토타입입니다. 새로고침하면 입력한 예약이 사라지고, 결제 버튼은 실제로 돈이 오가지 않습니다. 아래 6단계를 순서대로 밟으면 같은 화면 그대로 진짜 서비스가 됩니다. 개발을 직접 하지 않아도 되는 구간과, 반드시 사람이 신청해야 하는 구간을 나눠 적었습니다.

예상 기간
3 ~ 5주
PG 심사가 가장 오래 걸립니다
월 고정비
0 ~ 3.5만원
초기엔 무료 요금제로 충분합니다

4가지

먼저 알아둘 것

제가 할 수 있는 일과 없는 일

저는 화면과 코드를 만들 수 있지만, 대표님 명의로 계정을 만들거나 서류를 제출할 수는 없습니다. 결제 대행사(PG) 심사, 사업자등록증 제출, 카카오 채널 인증 같은 것은 본인 확인이 필요하기 때문입니다. 그래서 아래처럼 나뉩니다.

제가 해드릴 수 있는 것
· 데이터베이스 설계와 SQL 전문
· 보안 정책(RLS)·RPC 함수 작성
· 화면을 실제 DB에 연결하는 코드
· 결제 연동 코드 (키만 넣으면 동작)
· 배포 설정 파일 일체
대표님이 직접 하셔야 하는 것
· Supabase · Vercel 계정 가입
· 도메인 구매 (연 1~2만원)
· 토스페이먼츠 가맹 신청 + 서류
· 카카오 비즈니스 채널 인증

STEP 1 · 1일

데이터 저장소 만들기 (Supabase)

예약 정보가 영구히 남는 곳입니다. 구글 계정으로 가입하면 5분이면 끝납니다.

  1. supabase.com 접속 → GitHub 또는 구글 계정으로 가입
  2. New project → 이름 romancestory, 리전은 Northeast Asia (Seoul) 선택
  3. DB 비밀번호를 정하고 따로 안전하게 메모 (분실 시 재설정 번거로움)
  4. 왼쪽 메뉴 SQL Editor → 제가 드리는 SQL 전문을 붙여넣고 Run
  5. 왼쪽 메뉴 Settings → API 에서 Project URL 과 anon key 두 값을 복사해 저에게 전달
anon key는 공개되어도 되는 키입니다. 대신 service_role 키는 절대 남에게 보내지 마세요. 그 키 하나로 모든 데이터를 지울 수 있습니다.

만들어질 테이블

테이블 담는 내용 누가 볼 수 있나
projects예약·문의 전체 (이름, 연락처, 예식일, 금액, 입금액, 상태, 납품 링크)관리자만
payments입금 내역 1건씩 (예약금/잔금, 금액, 수단, 승인번호)관리자만
app_settings홈페이지 문구, 패키지 가격, 옵션, 출장 지역, 메시지 템플릿누구나 읽기 / 관리자만 수정
contracts계약서 스냅샷과 전자서명 시각·IP관리자 + 본인

보안 — 이 부분이 가장 중요합니다

고객 연락처가 들어있는 표를 홈페이지에서 그냥 불러오면, 브라우저 개발자도구로 전체 고객 명단이 통째로 보입니다. 실제 웨딩 업체 사고 중 가장 흔한 유형입니다. 그래서 두 겹으로 막습니다.

① RLS (행 수준 보안) — projects 테이블은 기본적으로 아무도 못 읽음으로 잠급니다. 로그인한 관리자만 통과합니다.
② RPC 함수 — 방문자에게 꼭 필요한 정보만 함수로 뚫어줍니다.
get_public_booking_dates() → 날짜와 마감 여부만 반환. 이름·연락처는 아예 나가지 않음
verify_client_booking(이름, 연락처) → 두 값이 정확히 일치할 때만 본인 1건 반환
get_payment_summary(이름, 연락처) → 결제 탭용. 금액·잔금만 반환

STEP 2 · 2~3일

화면을 데이터베이스에 연결

이 단계는 제가 합니다. 지금 코드는 데이터를 다루는 함수가 한곳에 모여 있어서, 그 안쪽만 Supabase 호출로 바꾸면 화면은 손대지 않아도 됩니다.

· 예약 폼 접수 → projects insert
· 칸반 드래그 → status update
· 상세 모달 저장 → 해당 행 update
· 홈페이지 관리(CMS) 저장 → app_settings update, 즉시 반영
· 관리자 로그인 → Supabase Auth 이메일 로그인으로 교체 (지금은 누구나 관리자 탭에 들어갈 수 있는 상태입니다)
지금 상단의 홈 / 고객 조회 / 결제 / 관리자 탭은 데모용입니다. 실서비스에서는 관리자 화면을 /admin 주소로 분리하고, 로그인하지 않으면 아예 열리지 않게 막습니다.

STEP 3 · 1일 + 심사 대기

결제 붙이기

웹사이트에서 카드 결제를 받으려면 반드시 PG사(결제대행사)를 거쳐야 합니다. 개인 계좌로 카드를 받는 방법은 없습니다. 세 가지 선택지가 있고, 동시에 여러 개를 쓰셔도 됩니다.

방법 수수료 준비 기간 추천
계좌 이체0%즉시지금 당장. 잔금처럼 큰 금액에 유리
카카오페이 송금0%즉시상담이 카톡으로 이뤄지므로 자연스러움
토스페이먼츠카드 2.9% 내외2~3주 심사카드·할부를 원하는 고객용

토스페이먼츠 신청 순서

  1. 사업자등록증 준비 (없으면 홈택스에서 온라인 신청, 업종: 영상촬영업)
  2. tosspayments.com → 가맹점 신청 → 개인사업자 선택
  3. 제출 서류: 사업자등록증 · 대표자 신분증 · 통장 사본 · 홈페이지 주소
  4. 심사 2~3주. 이때 홈페이지에 이용약관 · 개인정보처리방침 · 환불규정 · 사업자정보 푸터가 없으면 반려됩니다 → 제가 미리 만들어 둡니다
  5. 승인되면 발급되는 클라이언트 키 · 시크릿 키를 저에게 전달 → 결제 탭이 실제로 동작
심사 대기 중에도 서비스는 열 수 있습니다. 결제 탭에 계좌 이체와 카카오 송금만 켜두고, 카드 결제는 승인 후 스위치 하나로 활성화합니다.

STEP 4 · 반나절

인터넷에 올리고 주소 연결

  1. 도메인 구매 — 가비아 또는 Cloudflare에서 romancestory.kr 같은 주소 구입 (연 1~2만원)
  2. Vercel 가입 — vercel.com, 무료 요금제로 충분합니다
  3. 제가 코드를 GitHub에 올리면 Vercel이 자동으로 배포합니다
  4. Vercel의 Domains 메뉴에 구매한 주소를 입력 → 안내되는 값을 도메인 업체 DNS에 붙여넣기
  5. HTTPS 자물쇠는 자동으로 붙습니다
결과 주소 구조 — romancestory.kr 홈페이지 · /booking 예약 · /status 고객 조회 · /pay 결제 · /admin 관리자(로그인 필요)

STEP 5 · 1~2일

카카오톡 자동 알림

지금은 CRM에서 문구를 복사해 직접 붙여넣는 방식입니다. 알림톡을 붙이면 예약 접수·입금 확인·납품 완료 순간에 자동으로 발송됩니다. 건당 8~15원 수준입니다.

  1. 카카오 비즈니스 채널을 비즈니스 인증 (사업자등록증 필요)
  2. 알림톡 대행사 가입 — 솔라피, 알리고, NHN Toast 중 택1
  3. 템플릿 등록 후 카카오 심사 1~2일 (광고 문구가 섞이면 반려됩니다)
  4. 승인된 템플릿 코드를 저에게 전달 → 상태 변경 시 자동 발송되도록 연결

STEP 6 · 상시

법적으로 반드시 있어야 하는 것

개인정보(이름·연락처)를 받고 돈을 받는 순간부터 아래는 선택이 아니라 의무입니다. PG 심사에서도 확인합니다.

· 개인정보 수집·이용 동의 체크박스 — 예약 폼에 필수
· 개인정보처리방침 페이지 — 보관 기간과 파기 시점 명시
· 이용약관 · 환불/취소 규정 — 예식 D-30 / D-7 기준 위약금을 명확히
· 푸터 사업자정보 — 상호 · 대표자 · 사업자등록번호 · 주소 · 연락처 · 통신판매업 신고번호
· 통신판매업 신고 — 정부24에서 온라인 신청 (등록면허세 연 4만원대)
